# Словарь цвета

[Открыть приложение](https://lavrlistoviy.github.io/color-dictionary/)

Небольшое веб-приложение с сочетаниями Санзо Вады: случайная палитра, подбор по одному или двум оттенкам, короткие русские пояснения, фильтры и избранное. Работает на GitHub Pages без сервера, ключей API, внешних шрифтов и библиотек.

В локальном каталоге **581 сочетание**: 348 из первого тома и 233 записи второго тома. Первый том — открытый MIT-набор Matt DesLauriers, второй — общедоступная оцифровка Wada.ink. **Второй том независимо не сверен с печатной книгой**; проверенный полный PDF не найден. Происхождение, точность экранных цветов и ограничения подробно описаны в [источниках](docs/SOURCES.md). Это неофициальное приложение.

## Запуск

Нужен Node.js 22 или новее. Устанавливать зависимости не требуется.

```powershell
cd color-dictionary
npm start
```

Откройте адрес из терминала: по умолчанию `http://127.0.0.1:4173/`. Двойной щелчок по `index.html` не подходит: браузер загружает локальный JSON через HTTP.

## Использование

- **Случайная палитра:** кнопка «Новое сочетание» выбирает палитру из текущей выборки. Непосредственного повтора нет, если доступны хотя бы две палитры.
- **Подобрать по цвету:** введите HEX из 3 или 6 символов либо используйте цветовой диалог. Второй оттенок добавляется отдельной кнопкой. Нажмите «Найти сочетания».
- **Фильтры:** том и число цветов применяются к любому режиму. Коллекция содержит палитры от 2 до 9 цветов; не каждая комбинация фильтров даёт результат.
- **Копирование:** нажатие на цвет или HEX копирует код. «Копировать палитру» копирует все HEX через запятую.
- **Избранное:** сердечко сохраняет палитру в `localStorage` текущего браузера. При очистке данных сайта избранное исчезнет. Если хранилище запрещено, избранное остаётся до закрытия вкладки.

Подбор сравнивает цвета в Oklab. Для двух входных оттенков перебираются назначения **двум разным образцам** палитры, затем минимизируется средняя дистанция. При равенстве предпочтение получает меньшая максимальная дистанция. Поэтому один удачный оттенок не считается совпадением сразу для двух введённых цветов. Палитры книги остаются неизменными; пользовательские цвета показаны рядом для сравнения. «Ближайшее» означает ближайшее среди выбранного каталога, а не обязательное точное совпадение.

Пояснения алгоритмические: они описывают светлоту, насыщенность, цветовую температуру и контраст. Это собственные интерпретации приложения, а не текст Вады или издателя. Английские названия оттенков сохранены из источников.

## GitHub Pages

1. Поместите содержимое проекта в свой GitHub-репозиторий.
2. В **Settings → Pages → Build and deployment → Source** выберите **GitHub Actions**.
3. Отправьте изменения в `main` или `master`, либо вручную запустите **Actions → Deploy to GitHub Pages → Run workflow**.
4. После успешного выполнения адрес сайта появится в запуске workflow и в **Settings → Pages**.

Workflow [`.github/workflows/pages.yml`](.github/workflows/pages.yml) запускает тесты, собирает `dist/` и публикует этот каталог. Токены вручную добавлять не нужно. Для другой основной ветки измените `on.push.branches`. Аккаунт GitHub должен поддерживать Pages для выбранного типа репозитория. [Документация GitHub](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

Все ссылки на ресурсы относительные: приложение работает и в корне домена, и по адресу `https://username.github.io/repository/`.

Можно опубликовать вручную содержимое `dist/` на любом статическом хостинге:

```powershell
npm test
npm run build
node scripts/serve.mjs --dist --base=color-dictionary --port=4180
```

Последняя команда проверяет сборку по адресу `http://127.0.0.1:4180/color-dictionary/`, имитируя путь репозитория GitHub Pages.

## Проверки

```powershell
npm test
npm run build
```

Тесты проверяют преобразования цветов, ранжирование пары, целостность обеих частей каталога, известные составы палитр и обработку девятицветных сочетаний. Ручные сценарии — в [чек-листе QA](docs/QA.md).

## Структура

| Файл | Назначение |
| --- | --- |
| `index.html`, `src/styles.css` | Интерфейс и адаптивная вёрстка |
| `src/app.js` | Состояние интерфейса, копирование, избранное |
| `src/color-engine.js` | Цветовые преобразования, подбор и пояснения |
| `data/catalog.json` | Локальный каталог палитр и оттенков |
| `data/source-manifest.json` | Адреса и контрольные суммы источников |
| `scripts/import-catalog.mjs` | Повторный импорт фактических данных |
| `scripts/build.mjs`, `scripts/serve.mjs` | Сборка и локальный предпросмотр |

Обновление данных требует отдельной проверки источников; оно не выполняется при сборке или открытии сайта. Порядок описан в [источниках](docs/SOURCES.md). Уведомления сторонних авторов сохранены в [THIRD_PARTY_NOTICES.txt](THIRD_PARTY_NOTICES.txt).
